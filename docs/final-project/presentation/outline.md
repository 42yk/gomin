# 고민일기 발표 구성과 시연 대본

## 프로젝트 소개

고민일기는 혼자 글로 정리하기 어려운 마음을 AI 친구 모리와의 대화로 풀고, 한 장의 그림일기로 남기는 웹 서비스다. 심리 상담을 받고 싶거나 받고 있는 만 10~24세 청소년·청년을 1차 대상으로 정했다.

기획에서 주목한 문제는 말을 꺼내기 어렵다는 점, 대화 뒤에 자신의 고민을 한눈에 정리하기 어렵다는 점, 긴 기록을 다시 읽는 부담이다. 모리와의 대화, 고민·감정 요약, 그림일기와 컬렉션을 하나의 이용 흐름으로 연결했다.

자료: [프로젝트 소개](../overview.md), [기획서](../proposal.md).

## 서비스 시연

| 순서 | 화면 동작 | 설명할 내용 |
| --- | --- | --- |
| 1 | 로그인 후 털어놓기 진입 | 사용자는 정리된 글 대신 짧은 대화로 시작한다. |
| 2 | 모리와 대화 | 앞선 대화를 바탕으로 응답하고 사용자가 원할 때 마무리한다. |
| 3 | 요약 확인·확정 | 지금의 마음·주요 고민·감정 태그를 확인한다. 더 이야기하고 싶다면 같은 대화로 돌아갈 수 있다. |
| 4 | 그림일기 생성 | 확정 요약으로 모리가 등장하는 그림과 제목·위로 문구를 만든다. |
| 5 | 컬렉션 저장·조회 | 저장한 그림과 원본 요약을 다시 살펴본다. |

시연 주소: [www.gomin.today](https://www.gomin.today). 위 순서는 구현된 기능을 설명하는 시연 구성이다.

## 시스템과 AI 활용

Next.js가 화면을 제공하고 FastAPI가 인증·AI 호출·저장을 처리한다. 대화·요약·그림 구성은 Copa의 텍스트 API를, 이미지는 Gemini를 사용한다. DB·파일은 Supabase에 저장한다.

대화 AI에는 해당 대화의 저장 원문을 전달한다. 그림 생성에는 확정 요약의 핵심 상황과 모리 참조 이미지를 사용한다. 서버에서 소유권·출력 구조·이미지 형식을 확인하고 실패와 완료를 구분한다.

자료: [시스템 구성과 AI 활용](../technical-report.md).

## 사용자 피드백과 개선

실사용자 5명이 배포 환경을 이용했고 대면으로 피드백을 받았다. 참여자는 기획 타겟과 다른 사용자들이다.

입력창 자동 초점, 컬렉션 상세의 좌우 배치, 로딩 안내를 개선했다. 다음 고민을 유도하는 정형적인 대화와 고민에 맞지 않는 그림에 대해서는 대화·이미지 프롬프트를 수정했다. 수정 효과의 만족도나 성공률은 측정 결과가 없어 발표 수치로 제시하지 않는다.

자료: [테스트 결과](../user-testing/results.md), [피드백과 개선](../user-testing/improvements.md).

## 역할과 확인한 결과

네 명이 공동으로 기획하고 회원·인증, 대화·요약, 그림일기·컬렉션, QA로 담당 범위를 나눴다. 배포 환경에서 대화부터 저장·재조회까지의 흐름을 담당자가 확인했다. 자동·격리 검증 결과는 기존 QA 기록의 범위로 설명한다.

자료: [팀 역할과 협업](../collaboration.md), [검증·배포 결과](../verification.md).

## 결과를 설명할 때의 범위

타겟 사용자에 대한 효과, 프롬프트 수정 후 품질 개선, 응답 속도·가용성은 측정된 성과로 제시하지 않는다. 구현 결과와 사용자 의견, 코드 변경으로 확인한 사실을 중심으로 발표한다.
